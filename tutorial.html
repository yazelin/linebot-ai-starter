LINE Bot AI 入門模板：快速開始

本機這一段（安裝、啟動、簽章驗證）完全不需要 LINE 帳號。要讓真的 LINE 使用者收到回覆，才需要你自己的 channel。

第一步：取得程式碼並建立虛擬環境

git clone https://github.com/yazelin/linebot-ai-starter.git
cd linebot-ai-starter
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

第二步：準備環境變數

cp .env.example .env

第一次先不要動，保持 AI_PROVIDER=echo。echo 模式不需要任何金鑰，最適合確認整條路通不通。

第三步：啟動服務

uvicorn app.main:app --reload --port 8000

成功的話你會看到（本機實際輸出）：

INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)

第四步：健康檢查

curl http://127.0.0.1:8000/health

成功的話你會看到：

{"ok":true}

第五步：本機模擬簽章驗證（不用 LINE 帳號）

LINE webhook 會附 X-Line-Signature，是用 channel secret 對 raw body 做 HMAC-SHA256 再 base64。我們可以在本機自己算一個正確簽章證明它有效。把下面存成 sig_demo.py：

import base64, hashlib, hmac, json, os
os.environ["LINE_CHANNEL_SECRET"] = "test_secret_123"
os.environ["LINE_CHANNEL_ACCESS_TOKEN"] = "dummy"
os.environ["AI_PROVIDER"] = "echo"
from fastapi.testclient import TestClient
from app.main import app
client = TestClient(app)
body = json.dumps({"events": []}).encode("utf-8")
def sign(secret, raw):
    return base64.b64encode(hmac.new(secret.encode(), raw, hashlib.sha256).digest()).decode()
good = sign("test_secret_123", body); bad = sign("WRONG_secret", body)
print("[valid]  ", client.post("/webhook/line", content=body, headers={"X-Line-Signature": good}).status_code)
print("[wrong]  ", client.post("/webhook/line", content=body, headers={"X-Line-Signature": bad}).status_code)
print("[missing]", client.post("/webhook/line", content=body).status_code)

執行 python sig_demo.py，本機模擬簽章驗證的真實輸出（本機模擬，不是真的 LINE 呼叫）：

[valid]   200
[wrong]   403
[missing] 403

正確簽章放行、錯誤或沒帶簽章擋掉，證明簽章驗證真的在擋人。

本機到此你已驗證

  • 服務能啟動（看到 Application startup complete.）
  • /health 回 {"ok":true}
  • 簽章正確放行、錯誤擋掉（200 / 403）
  • secret 沒有 commit 進 GitHub（.env 已被 .gitignore 排除）

要讓真的 LINE 使用者收到回覆（需要你自己的 channel）

  1. 到 LINE Developers console 建一個 Messaging API channel。
  2. 把 Channel secret 填 LINE_CHANNEL_SECRET、Channel access token 填 LINE_CHANNEL_ACCESS_TOKEN。
  3. 用 ngrok http 8000 開一條公開 HTTPS 通道，拿到像 https://xxxx.ngrok-free.app 的網址。
  4. 在 console 把 Webhook URL 設成 https://xxxx.ngrok-free.app/webhook/line，打開 Use webhook、關掉 Auto-reply。
  5. 設好你的 channel access token 後，加 bot 為好友傳訊息，會收到 LINE AI echo: 你打的字。

回覆透過 POST https://api.line.me/v2/bot/message/reply 加 Bearer token 送出，一定要有真的 access token 才會成功。

LINE Bot AI 入門模板：架構說明

核心檔案

  • app/main.py：FastAPI webhook 入口與 LINE signature 驗證
  • app/line.py：處理 LINE events、reply API
  • app/ai.py：AI provider adapter，支援 echo / claude-cli / gemini-cli / HTTP API
  • app/config.py：從 .env 載入 token 與模型設定

資料流

  1. 使用者或 client 發出請求。
  2. FastAPI / stdio 入口接收資料。
  3. handler 解析訊息與設定。
  4. adapter / tool / search 層執行實際工作。
  5. 回傳最小可理解的結果。

設計原則

  • 先讓流程可跑，再做漂亮抽象。
  • token 與 secrets 全部放在環境變數。
  • 每一層保持可以替換：入口、AI provider、資料來源、部署方式。
  • 範例程式刻意保持小，方便你看懂後改成自己的版本。

LINE Bot AI 入門模板：完整操作流程

帶你走一遍：本機跑出 200/403、親手重現 fail-closed、找到回覆邏輯在哪改，最後做一個動手練習看改前改後差異。除了最後上線提醒，全程不需要 LINE 帳號。

步驟 1：echo 模式啟動

uvicorn app.main:app --reload --port 8000

步驟 2：本機模擬簽章驗證

app/line.py 的 verify_signature 用 channel secret 對 raw body 算 HMAC-SHA256、base64、再常數時間比對。用快速開始那段的 sig_demo.py 即可在本機跑出（真實輸出）：

[valid signature]   200
[wrong signature]   403
[missing signature] 403

送 {"events": []}（空清單）所以不會觸發回覆，不需要真 token。

步驟 3：親手重現 fail-closed

沒設 LINE_CHANNEL_SECRET 時，只有 AI_PROVIDER=echo 或 LINE_ALLOW_INSECURE=1 才放行，其餘回 403。對應 app/line.py：

if not LINE_CHANNEL_SECRET:
    if AI_PROVIDER == "echo" or os.getenv("LINE_ALLOW_INSECURE") == "1":
        return True
    return False

本機重現的真實輸出：

secret=(空), AI_PROVIDER=echo, LINE_ALLOW_INSECURE=None -> 200
secret=(空), AI_PROVIDER=http, LINE_ALLOW_INSECURE=None -> 403
secret=(空), AI_PROVIDER=http, LINE_ALLOW_INSECURE=1 -> 200

切到真 provider 又沒 secret 直接 403，這是在保護你。正式上線一定要設真的 LINE_CHANNEL_SECRET。

步驟 4：找到回覆邏輯在哪裡

bot 收到文字怎麼決定回什麼，全在 app/line.py 的 handle_events：

text=e["message"]["text"]; reply="pong" if text=="/ping" else await ask_ai(text)
await reply_text(e["replyToken"], reply[:4500])

加固定關鍵字回覆 -> 改 app/line.py；改 AI 怎麼回 / 換 provider -> 改 app/ai.py。

步驟 5：動手練習 — 加一個關鍵字自動回覆

目標：使用者打「營業時間」時直接回固定答案。用一個假的 reply_text 攔截回覆，不需要真 token 就能看 bot 會回什麼。存成 exercise.py：

import asyncio, os
os.environ["AI_PROVIDER"] = "echo"; os.environ["LINE_CHANNEL_ACCESS_TOKEN"] = "dummy"
import app.line as line
captured = []
async def fake_reply(token, text): captured.append(text)
line.reply_text = fake_reply
async def main():
    for msg in ["/ping", "hello", "營業時間"]:
        captured.clear()
        await line.handle_events({"events":[{"type":"message","replyToken":"TK",
            "message":{"type":"text","text":msg}}]})
        print(f"輸入 {msg!r:10} -> 回覆 {captured[0]!r}")
asyncio.run(main())

改之前的真實輸出：

輸入 '/ping'    -> 回覆 'pong'
輸入 'hello'    -> 回覆 'LINE AI echo: hello'
輸入 '營業時間'    -> 回覆 'LINE AI echo: 營業時間'

在 app/line.py 的 handle_events 上面加一張關鍵字表，並讓 handler 先查表：

KEYWORD_REPLIES = {
    "/ping": "pong",
    "營業時間": "我們的營業時間是週一到週五 09:00-18:00。",
}
async def handle_events(payload):
    for e in payload.get("events",[]):
        if e.get("type")!="message" or e.get("message",{}).get("type")!="text": continue
        text=e["message"]["text"]
        reply=KEYWORD_REPLIES[text] if text in KEYWORD_REPLIES else await ask_ai(text)
        await reply_text(e["replyToken"], reply[:4500])

再跑一次 python exercise.py，改之後的真實輸出：

輸入 '/ping'    -> 回覆 'pong'
輸入 'hello'    -> 回覆 'LINE AI echo: hello'
輸入 '營業時間'    -> 回覆 '我們的營業時間是週一到週五 09:00-18:00。'

「營業時間」那行從 echo 變成你的固定答案，其它訊息照舊。練習完成。

LINE Bot AI 入門模板：常見問題與踩雷清單

1. 簽章驗證一直 403（明明 secret 是對的）

簽章是對 raw body 的 bytes 算的。如果中間有人把 JSON 重新序列化（先 loads 再 dumps、或 proxy 改了空白 / key 順序 / 編碼），算出來的 bytes 跟 LINE 當初簽的不同，HMAC 對不上 -> 403。本 starter 直接拿 await request.body() 原始 bytes 去驗，沒有重序列化。修法：別在驗簽章前動 body，前面的 nginx / Cloudflare 也別改 request body。

2. 忘了設 secret，webhook 全被擋（fail-closed）

這是刻意的。沒 LINE_CHANNEL_SECRET 時只有 AI_PROVIDER=echo 或 LINE_ALLOW_INSECURE=1 才放行，其餘 403。本機重現（真實輸出）：

secret=(空), AI_PROVIDER=echo, LINE_ALLOW_INSECURE=None -> 200
secret=(空), AI_PROVIDER=http, LINE_ALLOW_INSECURE=None -> 403
secret=(空), AI_PROVIDER=http, LINE_ALLOW_INSECURE=1 -> 200

修法：正式上線就把真的 LINE_CHANNEL_SECRET 設好。沒密鑰任何人都能偽造 LINE webhook。

3. 收得到 webhook，但使用者沒收到回覆（reply 401）

uvicorn 顯示 POST /webhook/line ... 200 OK 但 LINE 裡沒回覆。回覆是另一個動作：reply_text 打 POST https://api.line.me/v2/bot/message/reply，帶 Authorization: Bearer <LINE_CHANNEL_ACCESS_TOKEN>。token 沒設 / 設錯 / 過期，LINE 回 401，但 webhook 本身仍是 200，容易被忽略。修法：確認 access token 有效，別把 channel secret 和 access token 貼反。

4. ngrok 開了，但 LINE 還是沒打進來

常見原因：Webhook URL 沒設或漏了 /webhook/line；Use webhook 沒開；ngrok 網址換了但 console 還指舊網址；ngrok port 跟 uvicorn 不同。修法：用 console 的 Verify 按鈕測 webhook URL，換 ngrok 網址後記得更新。

5. replyToken 用過就失效

replyToken 只能用一次、時效很短（約一分鐘）。長任務改用 push message（/v2/bot/message/push，以 user id 為對象），不要重複用 replyToken。

6. 個資直送第三方 LLM

切到 http / claude-cli / gemini-cli provider 後，使用者打的字會原封不動送到外部 LLM。正式前先想清楚哪些能外送，必要時在 app/ai.py 加過濾。

Debug 順序

  1. 先確認服務有沒有啟動。
  2. 再確認 endpoint / webhook URL 是否正確。
  3. 檢查環境變數是否有載入。
  4. 用 echo / fake provider 排除 AI 服務問題。
  5. 查看完整錯誤訊息，不要只看最後一行。
  6. 把問題縮到最小可重現案例。

問別人前準備

  • repo / branch
  • 啟動指令
  • 完整錯誤訊息
  • 你已經檢查過哪些設定
  • secret 請遮掉，不要直接貼 token

LINE Bot AI 入門模板：改成你的使用場景

可延伸方向

  • 客服：加入 FAQ、人工轉接、營業時間判斷。
  • 點餐：把 message 轉成 intent，再接菜單與訂單資料庫。
  • 公司通知：接 Google Sheets、Notion、ERP 或 webhook。
  • 群組助理：根據 group id 控制可用功能。

改造原則

  • 一次只改一個層次：先改資料來源，再改 UI，再改部署。
  • 先保留原本可跑的範例，另開 branch 做實驗。
  • 每加一個外部服務，就加一個健康檢查或 smoke test。
  • 先做 PoC，再決定要不要產品化。

適合拿來做課程 / 工作坊的題目

  • 從零跑起這個 starter。
  • 改成自己的真實場景。
  • 加入權限、部署與監控。
  • 現場 debug 學員遇到的問題。
